先準備

  1. Nextline 已經在跑（見安裝與第一次登入）。
  2. 產生 token 並放進環境變數 NEXTLINE_API_TOKEN，例如寫在 ~/.zshenv（見產生 token）。

加入 MCP server

用單引號，讓 ${NEXTLINE_API_TOKEN} 原樣存進設定，連線時才由 Claude Code 展開，token 不會寫進 ~/.claude.json：

```sh claude mcp add --transport http --scope user nextline http://127.0.0.1:3000/mcp \ --header 'Authorization: Bearer ${NEXTLINE_API_TOKEN}' ```

或寫在專案的 .mcp.json：

```json { "mcpServers": { "nextline": { "type": "http", "url": "http://127.0.0.1:3000/mcp", "headers": { "Authorization": "Bearer ${NEXTLINE_API_TOKEN}" } } } } ```

Nextline 放在伺服器或 Cloudflare 上時，把網址換成自己的 https://…/mcp。

確認連上了

```sh claude mcp list ```

看到 nextline 是 connected 就好。工具名稱是 mcp__nextline__list_issues、mcp__nextline__save_issue 等，完整清單見 MCP 工具。

連不上時先看：token 環境變數在啟動 Claude Code 的那個 shell 裡有沒有值；token 是不是被重新產生過（舊的會立刻失效，回 401）。

試一次

在對話裡直接說，例如：

  • 「列出 Nextline 上 Todo 的票」
  • 「讀 NX-3，照描述做完，comment 寫做了什麼和下一步，送待驗收」

建議 agent 寫 comment 時帶 author、改票時帶 actor（例如 my-repo agent），變更紀錄才分得出是誰改的；沒帶會記成 mcp。

要讓 agent 每次都照同一套格式開票、回報、送待驗收，把給 agent 的協作規範的範本貼進 repo 的 CLAUDE.md。
