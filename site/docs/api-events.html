方法與路徑做什麼
GET /api/issues/:ref/events一張票的變更紀錄，舊到新
POST /api/issues/:ref/events/:id/revert還原第 :id 筆

哪些修改會記

  • 記：標題、描述、狀態、Project、Sprint、到期日、blocked by、封存。一個請求改了幾個欄位就寫幾筆，跟修改一起成功或一起失敗。
  • 不記：開票本身（起始值看票的 created_at）、只調整看板位置、值沒有真的變的欄位、comment。

列出變更紀錄

GET/api/issues/:ref/events 回 { "events": [...] }，舊到新。

每一筆

idnumber

第幾筆。

issue_numbernumber
fieldstring

title、description、status、project、sprint、due_date、blocked_by、archived。

from_value、to_valuestring | null

舊值、新值，都是文字。project、sprint 是 id；blocked_by 是擋住這張票的票號數字（加入是 null → "3"，移除反過來）；archived 是封存時間。

actorstring

誰改的。

revert_of_event_idnumber | null

這筆是「還原了第 N 筆」時的 N。

reverted_by_event_idnumber | null

這筆已經被還原時，是還原它的那一筆。

created_atISO 時間

請求

curl -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  http://127.0.0.1:3000/api/issues/NX-13/events

回應 200

{
  "events": [
    {
      "id": 87,
      "issue_number": 13,
      "field": "status",
      "from_value": "Todo",
      "to_value": "In Review",
      "actor": "my-agent",
      "revert_of_event_id": null,
      "reverted_by_event_id": null,
      "created_at": "2026-11-20T09:12:40.118Z"
    }
  ]
}

還原一筆變更

POST/api/issues/:ref/events/:id/revert 把第 :id 筆的欄位改回 from_value，寫一筆新的紀錄（revert_of_event_id = :id），並把第 :id 筆標成已還原。全部在同一次寫入完成。

內容（可以不帶）

actorstring

誰還原的，預設 api。

回應 200

issue

還原後的票。

event

新寫的那筆。

reverted_event

被還原的那筆。

請求

curl -X POST -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"actor":"my-agent"}' \
  http://127.0.0.1:3000/api/issues/NX-13/events/87/revert

回應 409

{
  "error": "第 87 筆已經在第 90 筆還原過了",
  "reverted_by_event_id": 90
}

還原狀態跟一般改狀態一樣：completed_at／canceled_at 會跟著改，票放到那一欄最上面。

不能還原的情況

狀態碼原因
404票不存在，或那筆紀錄不屬於這張票
409已經還原過；多帶 reverted_by_event_id
409之後同一個欄位又被改過（blocked_by 只看同一張擋住的票）；多帶 conflict_event_id。已經被還原掉的變更、以及「還原」本身不算，所以先還原後面那筆，就能再還原前面那筆
409欄位現在的值已經不是那筆改完的值
