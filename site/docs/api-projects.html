方法與路徑做什麼
GET /api/projects列出全部
POST /api/projects新增
GET /api/projects/:id讀一個（含長篇說明）
PATCH /api/projects/:id修改、釘選

票要放進 Project，用票的 project_id（見修改票）；列出某個 Project 的票用 GET /api/issues?project=<id>。

Project 的欄位

欄位說明
id數字
name名稱，不可重複
description長篇說明，Markdown（適合放規格）
linear_id搬資料用的外部 id，沒有是 null
created_at、updated_at建立、最後修改時間
pinned_at釘選時間，沒釘選是 null
last_activity_at只能讀：Project 本身、底下任一張票（含已封存）的更新時間、底下任一張票最新 comment 的時間，取最新的一個

列出 Project

GET/api/projects 回 { "projects": [...] }。釘選的在最上面（彼此照釘選時間新到舊），其餘照 last_activity_at 新到舊，同時間照名稱。網頁側欄用同一個順序列出前 7 個。

新增 Project

POST/api/projects 回 201 與存好的 Project。名稱重複回 409，帶既有 Project 的 id。

內容

namestring · 必填
descriptionmarkdown
linear_id、created_at、updated_at搬資料用

請求

curl -X POST -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"記帳 App","description":"## 目標\n…"}' \
  http://127.0.0.1:3000/api/projects

回應 201

{
  "id": 2,
  "name": "記帳 App",
  "description": "## 目標\n…",
  "pinned_at": null,
  "last_activity_at": "2026-11-20T09:20:11.002Z",
  …
}

讀一個 Project

GET/api/projects/:id 回 Project 的所有欄位；不存在回 404。

修改、釘選

PATCH/api/projects/:id 只改有帶的欄位，回改完的 Project。

內容

namestring

不能是空的、不可重複。

descriptionmarkdown
pinnedboolean

true 釘選、false 取消；已經是這個狀態就不動。釘選不算修改，不更新 updated_at。

請求

curl -X PATCH -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"pinned":true}' \
  http://127.0.0.1:3000/api/projects/2

Project 沒有狀態

Project 沒有「進行中／完成」這類狀態，回應裡也沒有 status。為了相容其他工具的習慣，新增或修改時帶 status 不會報錯，會直接忽略。Project 也不能刪除。
