跟 Node 跑法差在哪

程式是同一份（見一份核心、兩種跑法），差在登入方式：

路徑誰用怎麼驗證
/api/*、/mcpagentAuthorization: Bearer <token>，比對 Worker secret API_TOKEN
網頁與 /app-api/*你的瀏覽器Cloudflare Access（只放行你的 email），Worker 再驗一次 Access 的 JWT；寫入另外檢查同源
/health部署檢查不驗證，只回服務與資料庫是否正常

需要：Cloudflare 帳號（含 Zero Trust 的 Access）、Node（22.22 以上的 22.x 或 24.7 以上的 24.x）、在 repo 裡執行過 npm ci。

步驟

  1. 登入 Cloudflare：

    ```sh npx wrangler login ```

  2. 建立 D1 資料庫，把印出來的 database_id 填進 wrangler.jsonc 的 <your-d1-database-id>：

    ```sh npx wrangler d1 create nextline ```

  3. 套用資料表：

    ```sh npm run db:migrate:remote ```

  4. 設定 agent 用的 token（自己產生一組夠長的隨機字串，貼進提示）：

    ```sh npx wrangler secret put API_TOKEN ```

  5. 部署（會先自動建置前端）：

    ```sh npm run deploy ```

  6. 設定 Cloudflare Access：

    • Worker 設定 → Domains & Routes → workers.dev 開啟 Cloudflare Access，整個網址預設都要登入；policy 只放行自己的 email。
    • 另外建一個 self-hosted Access application，涵蓋 /health、/api/*、/mcp，policy 設成 Bypass，讓 agent 不會被導去登入頁（這些路徑由 Worker 驗 token）。/app-api 不要加進 Bypass。

  7. 把 Access 的值填進 wrangler.jsonc 的 vars，再部署一次：

    • ACCESS_TEAM_DOMAIN：https://<team 名稱>.cloudflareaccess.com
    • ACCESS_AUD：Zero Trust → Access → Applications → 第一個 application → Additional settings 的 Application Audience (AUD) Tag

    這兩個值有任何一個是空的，網頁一律回 403、/app-api 回 401（不會變成不驗證）。

確認

```sh curl -i https://<你的 Worker>.workers.dev/health ```
  • /health 回 200。
  • 無痕視窗打開網址，先被要求登入。
  • 不帶 token 打 /api/issues 回 401，而且不會被導到登入頁。

agent 的 MCP 網址改成 https://<你的 Worker>.workers.dev/mcp，token 用第 4 步設的值。

在本機試 Cloudflare 跑法

在 repo 根目錄建 .dev.vars（不會進 Git），放兩行：

```sh API_TOKEN=自己定的值 DEV_SKIP_ACCESS=1 ```

執行 npm run dev:cloudflare，開 http://127.0.0.1:5173。DEV_SKIP_ACCESS 只對 localhost／127.0.0.1 的請求有效，正式網址就算誤設也照樣驗；Node 跑法完全不讀這個開關。
