一句話

你在網頁上開票、拖拉、驗收；Claude Code、Codex 這類 agent 透過 API 或 MCP 讀票、寫 comment、改狀態。每張票現在輪到誰、下一步是什麼，看板上一眼就知道。介面是繁體中文。

一張票怎麼走

狀態固定六種，照看板欄的順序：

狀態意思
Backlog還沒排進來的想法
Todo要做、還沒開始
In Progressagent（或你）正在做
In Review介面顯示「待驗收」：做完了，等你看
Done完成
Canceled不做了
  1. 你開票，寫清楚要做什麼、做到什麼程度算完成，放到 Todo。
  2. agent 讀票、改成 In Progress，做完把結果寫成 comment，送到 In Review。comment 最後一行寫「下一步：…」，看板卡片就會顯示這一句。
  3. 你在待驗收的票上回覆。在網頁回覆後，票自動交回 In Progress，agent 下次來看就會接著做；要結束就把票移到 Done。

有什麼

  • 看板（拖拉排序）、全部的票（篩選、分組）、Project、票詳細、Cmd+K 指令面板，手機版也能用。
  • 每次修改都寫進變更紀錄，誰改的、從什麼改成什麼都看得到，可以一鍵還原。
  • 票可以設 blocked by，也可以封存（不做永久刪除）。
  • 給 agent 的 REST API 與遠端 MCP；MCP 常用工具的名稱和參數照 Linear MCP。
  • 兩種跑法共用同一份程式：Node＋SQLite 自己架，或部署到 Cloudflare Workers＋D1。

目前的限制

  • 只給一個人用：沒有註冊、沒有多人帳號（理由見為什麼只給一個人用）。
  • 所有 agent 共用一組 token，沒有個別權限；comment 的 author、變更紀錄的 actor 是 agent 自己填的文字，不是登入身分。
  • Nextline 不會主動通知或叫醒 agent。agent 什麼時候來看票，由你的排程或對話決定。
  • 沒有標籤、指派、優先度、估點這些欄位。

從哪裡開始

安裝與第一次登入五行指令在自己電腦上跑起來 讓 agent 開第一張票產生 token，用 curl 或 MCP 試一次 連上 Claude Code一行 claude mcp add REST API 參考票、comment、Project、變更紀錄
