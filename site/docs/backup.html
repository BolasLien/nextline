備份

目的地資料夾必須還不存在。服務開著也可以備份：

```sh export NEXTLINE_DATA_DIR="$HOME/.local/share/nextline" mkdir -p "$HOME/nextline-backups" npm run selfhost:backup -- "$HOME/nextline-backups/backup-01" ```
  • 成功會顯示「備份完成，完整性與關聯驗證通過」，資料夾裡有一個 nextline.sqlite。
  • 用 SQLite 的線上備份，已提交的寫入都會包含。不要直接 cp 正在用的資料庫檔。
  • 備份裡有密碼雜湊、token 雜湊與登入 session，跟正式資料一樣要放在私人的地方。

還原

先停掉服務（前景執行就按 Ctrl+C），再還原到另一個新的資料夾：

```sh npm run selfhost:restore -- "$HOME/nextline-backups/backup-01" "$HOME/.local/share/nextline-restored-01" export NEXTLINE_DATA_DIR="$HOME/.local/share/nextline-restored-01" npm run selfhost:init npm start ```

舊備份的資料表版本會由 selfhost:init 自動升級。確認方式：curl --fail http://127.0.0.1:3000/health，登入看一張已知的票、comment、變更紀錄，再讓 agent 用 MCP 讀同一張票。

還原後，密碼與 token 會回到備份當時的版本，之前撤銷的 token 可能重新有效。如果是因為外洩而還原，開放使用前先重設密碼並換 token。

更新到新版本

  1. 記下目前的版本（git rev-parse HEAD）與資料夾位置。把新版本放到另一個程式資料夾，執行 npm ci、npm run build；舊的程式資料夾先留著。
  2. 停掉服務，照上面做一次備份。備份成功前不要更新。
  3. 在新程式資料夾設定同一個 NEXTLINE_DATA_DIR，執行 npm run selfhost:init，再 npm start。
  4. 檢查 /health、登入、已知的票與 comment、API 與 MCP 讀寫。都正常才恢復使用。

新版本有問題時：停掉新服務，回到舊程式資料夾，把更新前的備份還原到另一個新資料夾，再用舊程式啟動。不能只退回程式卻繼續讀已經升級過的資料庫。

資料表升級怎麼保護資料

  • selfhost:init 在一個交易裡套用所有還沒套用的升級；任何一步失敗就整批撤回，資料不會停在一半。
  • 每個升級檔都記下 SHA-256。資料庫比程式新、或已套用的升級檔被改過，都會拒絕啟動。
  • 還原後如果已經有新寫入，回到舊快照會失去這些資料；沒有自動合併。
