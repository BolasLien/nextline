每個請求都要帶 Authorization: Bearer <token>，見認證與錯誤格式。
方法與路徑做什麼
GET /api/issues列出票，預設依更新時間新到舊
POST /api/issues開一張票，自動編號 NX-<n>
GET /api/issues/:ref讀一張票，含 blocked by 與 blocks
PATCH /api/issues/:ref修改，只改有帶的欄位；也用來調整看板順序與封存

票的欄位

欄位說明
number編號（數字）
identifier票號，NX-<number>
legacy_identifier從其他系統搬來的舊編號，沒有是 null
title標題
description描述，Markdown
statusBacklog、Todo、In Progress、In Review（待驗收）、Done、Canceled
position同一欄裡的順序，小的在上（見看板排序）
project_idProject id，沒有是 null
sprint_idSprint id，沒有是 null
due_date到期日 YYYY-MM-DD，沒有是 null
created_at、updated_at建立、最後修改時間
completed_at、canceled_at改成 Done／Canceled 時自動填，改成其他狀態就清掉
archived_at封存時間，沒封存是 null
next_step只能讀：最新一則 comment 裡「下一步：」後面的文字；最新那則沒寫就是 null。看板卡片顯示這一句

列出票

GET/api/issues 參數可以組合。沒帶參數就是全部沒封存的票。

查詢參數

statusstring

六種狀態之一；可逗號分隔（Todo,In Review）或重複帶（status=Todo&status=Done）。

sortupdated | position

updated（預設）是更新時間新到舊；position 是看板順序：先依狀態欄，欄內由上到下。

projectid | none

none 是沒有 Project 的票。

sprintid | none

none 是沒有 Sprint 的票。

updated_sinceISO 時間

updated_at 大於等於這個時間。

updated_beforeISO 時間

updated_at 小於這個時間。

archivedexclude | include | only

沒帶或 exclude 不含已封存的票；include 都要；only 只要已封存的。

limit、offsetnumber

limit 預設 50、最多 200；回應的 has_more 表示後面還有。

請求

curl -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  "http://127.0.0.1:3000/api/issues?status=Todo,In%20Review"

回應 200

{
  "issues": [
    {
      "identifier": "NX-12",
      "number": 12,
      "title": "月報表依分類畫圓餅圖",
      "status": "In Review",
      "next_step": "打開 /report 看 10 月的圓餅圖",
      "updated_at": "2026-11-20T08:29:53.024Z",
      …其他欄位見「票的欄位」
    }
  ],
  "limit": 50,
  "offset": 0,
  "has_more": false
}

開一張票

POST/api/issues 回 201 與存好的票（格式同讀一張票）。沒帶 status 就是 Backlog；沒指定位置就放在那一欄最上面。開票不寫變更紀錄。

內容

titlestring · 必填
descriptionmarkdown

預設空字串。

statusstring

預設 Backlog。直接開成 Done／Canceled 會自動填完成／取消時間。

project_id、sprint_idnumber

不存在回 400。

due_dateYYYY-MM-DD
before、after、position票號 | number

看板位置，一次只能帶一個，見看板排序。

legacy_identifierstring

搬資料用：舊系統的編號，例如 ABC-150（不能是 NX 編號）；已經有同一個舊編號回 409，帶既有票的 number、identifier。

created_at、updated_at、completed_at、canceled_atISO 時間

搬資料用：保留原本的時間；沒帶就用現在。

請求

curl -X POST -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"匯出 CSV","status":"Todo","project_id":2}' \
  http://127.0.0.1:3000/api/issues

回應 201

{
  "identifier": "NX-13",
  "number": 13,
  "title": "匯出 CSV",
  "description": "",
  "status": "Todo",
  "project_id": 2,
  "next_step": null,
  "blocked_by": [],
  "blocks": [],
  …
}

讀一張票

GET/api/issues/:ref 票的所有欄位，再加上 blocked_by（擋住這張的票）與 blocks（這張擋住的票）。已封存的票也查得到。

路徑參數

:refNX-12 | 12

也收舊編號，見票號。

blocked_by／blocks 每一項

identifier、number、legacy_identifier、title、status

請求

curl -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  http://127.0.0.1:3000/api/issues/NX-13

回應 200

{
  "identifier": "NX-13",
  "title": "匯出 CSV",
  "status": "Todo",
  …
  "blocked_by": [
    { "identifier": "NX-11", "number": 11,
      "legacy_identifier": null,
      "title": "建立資料表", "status": "In Progress" }
  ],
  "blocks": []
}

修改票

PATCH/api/issues/:ref 只改有帶的欄位，回改完的票（格式同讀一張票）。值真的有變的欄位各寫一筆變更紀錄，跟修改一起成功或一起失敗。

內容

titlestring

不能是空的。

descriptionmarkdown
statusstring

換欄又沒指定位置時，放到新那一欄最上面。

project_id、sprint_idnumber | null

null 移出。

due_dateYYYY-MM-DD | null

null 清掉。

archivedboolean

見封存。

before、after、position票號 | number

看板位置。只改位置不寫變更紀錄、不更新 updated_at。

actorstring

誰改的，寫進變更紀錄；預設 api。

請求

curl -X PATCH -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status":"In Review","actor":"my-agent"}' \
  http://127.0.0.1:3000/api/issues/NX-13

回應 200

{
  "identifier": "NX-13",
  "status": "In Review",
  "updated_at": "2026-11-20T09:12:40.118Z",
  …
}

看板排序

同一欄（同一個狀態）裡 position 小的在上。開票和修改都可以指定位置，三種方式一次只能帶一個（帶兩個以上回 400）：

欄位說明
before放在這張票的上面，例如 "NX-3"
after放在這張票的下面
position直接給整數
  • before／after 的票要在同一欄（換欄時是新的那一欄），否則回 400；指定自己或不存在的票也回 400。
  • 位置是間隔 1024 的整數；插到兩張中間取中間值，沒有空隙時整欄自動重新編號（順序不變）。

封存

Nextline 不做永久刪除。不要的票用 PATCH {"archived": true} 封存：看板、列表、Project 頁、側欄張數都不再算它；{"archived": false} 取消封存。

  • 封存會寫一筆變更紀錄（field 是 archived），可以用還原改回來。
  • 封存不改狀態與位置，取消封存後回到原本那一欄原本的位置。
  • 已經封存再送 true 不會有變化；開票時帶 archived 會被忽略。
  • 列出已封存的票：GET /api/issues?archived=only。
