架構

```text 瀏覽器（人） agent（Claude Code、Codex…） │ │ 網頁、/app-api /api、/mcp Node：密碼登入＋session Authorization: Bearer Cloudflare：Access │ └──────────────┬──────────────────────┘ ▼ 共用核心（API 路由、MCP 工具） │ ┌────────────────┴────────────────┐ SQLite 轉接（Node） D1 轉接（Workers） nextline.sqlite Cloudflare D1 ```

一樣的地方

  • 網頁呼叫的 /app-api/* 和 agent 呼叫的 /api/* 是同一套路由，路徑、參數、回應完全相同，只有驗證方式不同。後端加一個功能，人和 agent 同時拿到。
  • MCP 工具底層直接呼叫同一組 API 函式，所以 MCP 和 REST API 的行為一致（例如同樣寫變更紀錄、同樣的錯誤訊息）。
  • 資料表與升級檔（migrations/）兩邊共用。
  • 多筆寫入（例如改票加寫變更紀錄）在兩種資料庫都是同一個交易，失敗就整批撤回。

不一樣的地方

Node＋SQLiteCloudflare Workers＋D1
適合自己的電腦、自己的主機不想管主機，已經有 Cloudflare 帳號
人怎麼登入密碼（selfhost:init 設定），12 小時 sessionCloudflare Access（只放行你的 email）
agent tokenselfhost:token 產生，資料庫只存雜湊Worker secret API_TOKEN
HTTPS自己放反向代理（見架在伺服器上）Cloudflare 提供
備份selfhost:backup／selfhost:restoreNextline 沒有另外提供，用 Cloudflare D1 自己的備份功能
需要註冊服務不用Cloudflare 帳號

兩種跑法之間沒有內建的資料搬移工具。

怎麼確認兩邊一致

npm run verify 會把同一份 API／MCP 測試分別跑在 Node SQLite 與真正的 workerd D1 上（後者用 Miniflare 啟動）。改了共用核心，兩邊都要通過。
