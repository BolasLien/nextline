連線

項目值
網址Node 本機 http://127.0.0.1:3000/mcp；放到伺服器或 Cloudflare 時換成自己的 https://…/mcp
傳輸Streamable HTTP，只收 POST（GET、DELETE 回 405）
驗證Authorization: Bearer <token>，跟 REST API 同一組；沒有有效 token 回 401
狀態無狀態：不發 session id，每個請求各自處理，回 JSON（不開 SSE）
Accept 標頭要帶 Accept: application/json, text/event-stream，少一個回 406。Claude Code、Codex 會自己帶，用 curl 測才要注意

用 curl 確認連得上（列出工具）：

```sh curl -X POST http://127.0.0.1:3000/mcp \ -H "Authorization: Bearer $NEXTLINE_API_TOKEN" \ -H "Content-Type: application/json" \ -H "Accept: application/json, text/event-stream" \ -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' ```

client 設定見連上 Claude Code、連上 Codex。

回傳格式

  • 成功時 content[0].text 是 JSON 字串。
  • 找不到、參數不對、名稱重複時 isError: true，text 是中文錯誤說明。
  • 票號參數（id、issueId、blockedBy 等）收 NX-12、12 或舊編號，不分大小寫；回傳的票 id 一律是 NX-<n>，舊編號在 legacyIdentifier。
  • id 都是字串（projectId、cycleId、comment 的 id 是數字字串）。

工具一覽

工具做什麼
list_issues列出票
get_issue讀一張票（含描述與 blocked by）
save_issue開票或修改票
list_issue_events變更紀錄
revert_issue_event還原一筆變更
list_comments一張票的 comment
list_recent_comments跨票列出新的 comment
save_comment寫或改 comment
list_projects列出 Project
get_project讀一個 Project
save_project新增或修改 Project
list_cycles列出 Sprint（Linear 叫 Cycle）

list_issues

列出票，預設依更新時間新到舊、不含已封存的票。回 { issues, hasNextPage, cursor? }；每張票不含 description，要看內容用 get_issue。

參數說明
state狀態名稱，或 Linear 的 state type（backlog、unstarted、started、completed、canceled），不分大小寫；可逗號分隔。started 同時查 In Progress 與 In Review。沒做完的票：Backlog,Todo,In Progress,In Review
orderByupdatedAt（預設）或 position（看板順序）
projectProject 名稱（不分大小寫）或 id；none 是沒有 Project
cycleSprint 編號、名稱或 id（數字先當編號）；none 是沒有 Sprint
updatedAt這個時間之後更新的：ISO 時間、YYYY-MM-DD，或相對時間 -P1D、-P2W、-PT12H
includeArchivedtrue 才包含已封存的票（預設 false）
limit預設 50，最多 200（超過以 200 計）
cursor上一頁回傳的 cursor
team相容用，忽略

每張票的欄位：id、legacyIdentifier、title、status、statusType、project（名稱）、projectId、cycle（編號）、cycleId、dueDate、position、createdAt、updatedAt、completedAt、canceledAt、archivedAt。In Review 的 statusType 跟 Linear 一樣是 started。

get_issue

參數 id（必填）。回票的全部欄位，含 description 與 relations.blockedBy／relations.blocks（每項有 id、legacyIdentifier、title、status）。

save_issue

不帶 id 是開票（要 title），帶 id 是修改，只改有帶的欄位。回存完的票（同 get_issue）。所有參照（Project、Sprint、各個票號）會先檢查都存在才寫入，任何一個不存在就整個不寫。

參數說明
id要修改的票號；開票時不帶
title開票必填
descriptionMarkdown，整份替換
state狀態名稱或 state type（started 存成 In Progress）；開票預設 Backlog
projectProject 名稱或 id；null 移出
cycleSprint 編號、名稱或 id；null 移出
dueDateYYYY-MM-DD；null 清掉
before、after、position看板位置，一次只能帶一個，見看板排序；新票與換欄的票預設放最上面
blockedBy、blocks票號陣列，只新增關係
removeBlockedBy、removeBlocks票號陣列，拿掉關係
archivedtrue 封存、false 取消封存；只能修改時帶
actor誰改的，寫進變更紀錄；預設 mcp
team相容用，忽略

改到的每個欄位都寫一筆變更紀錄，做錯了用 revert_issue_event 還原。要人看過的票送 In Review。

list_issue_events

參數 issueId（必填）。回 { events }，舊到新；每筆有 id、issueId、field、from、to、actor、revertOf、revertedBy、createdAt。欄位意思見變更紀錄。

revert_issue_event

參數 issueId、eventId（必填）、actor（預設 mcp）。回 { issue, event, revertedEvent }：還原後的票、新寫的「還原了第 N 筆」、被還原的那筆。不能還原時（已經還原過、之後同一欄位又被改過、現在的值已經不同）以 isError 回中文說明，規則見不能還原的情況。

list_comments

參數 issueId（必填）。回 { comments }，舊到新；每則有 id、issueId、author、body、createdAt、updatedAt。

list_recent_comments

跨所有票列出某個時間之後新增的 comment，舊到新，包含 Done、Canceled 與已封存的票。適合 agent 一次找出「上次看過之後誰在哪些票留言」。

  • createdAt（必填）：ISO 時間、YYYY-MM-DD 或相對時間（例如 -P1D）。
  • limit（預設 50、最多 200）、cursor。

回 { comments, hasNextPage, cursor? }，每則格式同 list_comments。

save_comment

不帶 id 是在 issueId 的票上新增，帶 id 是修改那則的內容。

  • body（必填）：Markdown。最後一行寫「下一步：…」，看板卡片就會顯示。
  • issueId：新增時必填。
  • author：誰寫的，預設 mcp。建議帶 agent 自己的名稱。

agent 寫的 comment 不會改票的狀態；網頁使用者回覆待驗收的票才會把票交回 In Progress（見回覆待驗收的票會交回 agent）。

list_projects

參數 query（名稱包含這段文字，不分大小寫）；state、team 相容用、忽略。回 { projects }，釘選的在最上面，其餘照 lastActivityAt 新到舊；每個有 id、name、createdAt、updatedAt、pinnedAt、lastActivityAt，不含 description。

get_project

參數 query（必填，名稱或 id）。回 Project，含 description。

save_project

不帶 id 是新增（要 name，不可重複），帶 id（名稱或 id）是修改。參數：name、description、pinned（true 釘選、false 取消，只能修改時帶）；state 相容用、忽略。回存完的 Project。

list_cycles

參數 type：current、previous、next，不帶就是全部；teamId 相容用、忽略。回 { cycles }，依編號新到舊，每個有 id、number、name、startsAt、endsAt。
