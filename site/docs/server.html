做法

Nextline 不直接對外提供 HTTP。HTTPS 交給同一台機器上的反向代理（下面用 Caddy 示範），Node 照樣綁 127.0.0.1，只讓代理連進來。

```sh export NEXTLINE_DATA_DIR=/srv/nextline-data export NEXTLINE_PUBLIC_URL=https://nextline.example.com export NEXTLINE_TRUSTED_PROXIES=127.0.0.1 npm run selfhost:init npm start ```
  • NEXTLINE_PUBLIC_URL 是對外網址，只能有協定、主機與連接埠（不能有路徑）。
  • NEXTLINE_TRUSTED_PROXIES 是代理的精確 IP，逗號分隔；不接受萬用字元或網段。設成 HTTPS 網址卻沒設這個，服務會拒絕啟動。
  • 反過來，NEXTLINE_HOST 不是本機位址、卻沒有設 HTTPS 網址與代理時，也會拒絕啟動。

Caddy 設定範例

網域要先指到這台伺服器：

```caddyfile nextline.example.com { reverse_proxy 127.0.0.1:3000 { header_up Host nextline.example.com header_up X-Forwarded-Host nextline.example.com header_up X-Forwarded-Proto https } } ```

repo 的 docs/deploy/ 有可直接用的 public.Caddyfile（公開網域）、local.Caddyfile（沒有網域時用 localhost:8443 和自簽憑證演練）與 supervisord.conf（程序掛掉自動重啟）。

代理要符合的規則

  • 只接受來自指定代理 IP 的連線，而且 Host 要等於設定的網域、X-Forwarded-Proto 要剛好是 https。
  • 不看 Forwarded、X-Forwarded-For，公開網址也不從標頭推算。
  • 防火牆只讓代理連 Node 的連接埠，不要對外開。
  • HTTPS 模式下登入 cookie 會加上 Secure。

確認

```sh curl --fail https://nextline.example.com/health ```

回 {"ok":true,"db":"ok"} 就好。接著把 agent 的 MCP 網址換成 https://nextline.example.com/mcp。

完整的 Caddy＋Supervisor 演練步驟（含自簽 CA、停機備份、程序重啟）在 repo 的 docs/self-host.md。這份範例實測的是程序意外結束後自動重啟，沒有驗證整台主機重開或公開網域自動申請憑證。
